# 古籍库条目格式

古籍原文、白话与适用条件按篇存成 JSON（一般一篇一文件；几篇短章也可以合成一个文件，见下文 `section`），放在本目录下按书分的子目录里：

```
src/data/classics/
  ziwei/   《紫微斗数全书》            例：quanshu-zhuxing-wenda.json（诸星问答论）
  bazi/    《渊海子平》《三命通会》《滴天髓》《子平真诠》《穷通宝鉴》
  liuyao/  《增删卜易》《卜筮正宗》《京氏易传》《梅花易数》
```

**目录就是模块**：网页按 `bazi` / `ziwei` / `liuyao` 三个目录分块按需加载（看八字盘只下八字的古籍），所以文件只能放在这三个目录里，`applies` 的 `module` 也必须和所在目录一致，否则校验报错。

文件名用小写拼音加短横，格式：`<书名简称>-<篇名拼音>.json`。书的 key 必须是 `src/data/classics.js` 登记表里的（`ziwei`、`sanming`、`yuanhai`、`ditian`、`ziping`、`xieji`、`jingfang`、`bushi`、`zengshan`、`meihua`）；要录登记表里没有的书，先在 PR 里说明，由主线加登记。

提交前运行 `node scripts/validate-data.mjs`，CI 上也会跑同样的检查（`test/data-files.test.js`）。

## 文件结构

```json
{
  "classic": "ziwei",
  "volume": "卷一",
  "section": "诸星问答论",
  "edition": "所据版本与来源说明，例如：据明万历刻本影印本录入，参校通行本；文字来源 ctext.org",
  "contributor": "codex",
  "entries": [ … ]
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `classic` | 是 | 登记表里的书 key |
| `volume` | 否 | 卷次 |
| `section` | 是 | 篇名，照原书。一个文件录了几篇时，用「、」把各篇名依次列出（如 `论用神、论用神变化`），条目的 `title` 写成「篇名·其一」，程序据此把每条归到自己那一篇，出处只写这一篇 |
| `edition` | 是 | 所据版本、文字来源、是否参校，写清楚 |
| `contributor` | 否 | 谁录的（codex / antigravity / 人名） |
| `entries` | 是 | 条目数组，至少一条 |

## 条目结构

```json
{
  "id": "ziwei.quanshu.zhuxing.001",
  "title": "紫微星",
  "original": "问紫微所主若何？答曰：紫微属土，乃中天之尊星，为帝座，主掌造化枢机，人生主宰。",
  "vernacular": "问：紫微星主管什么？答：紫微五行属土，是中天最尊贵的星……",
  "notes": "「造化枢机」指天地化育万物的关键所在。",
  "doubts": ["「仗五行育万物」一句各本有异文。"],
  "applies": [{ "module": "ziwei", "star": "紫微" }],
  "tags": ["星曜", "主星"],
  "status": "translated"
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | 是 | 全库唯一；`书key.篇.小节.序号`，小写字母、数字、点、短横；序号三位 |
| `title` | 是 | 条目标题（星名、格局名、章节小题）；多篇文件里写「篇名·其N」 |
| `section` | 否 | 本条所属的篇。只在多篇文件里、且 `title` 不以篇名开头时才写，必须是文件 `section` 列出的篇名之一 |
| `original` | 是 | 原文。简体、全角标点，句读按通行本；段内换行用 `\n`；不改字、不删句、不加字 |
| `vernacular` | status 非 draft 时必填 | 白话。逐句对应，忠实原意，不夸张、不做现代化附会、不加原文没有的判断。长度一般是原文的 1.5～2.5 倍，超过 3.5 倍校验直接报错（原文不足 12 字不查） |
| `notes` | 否 | 注释：生僻词、典故、与程序口径的关系 |
| `doubts` | 否 | 存疑之处：异文、拿不准的句子，一条一句 |
| `applies` | 否 | 机器可读的适用条件，见下 |
| `tags` | 否 | 分类标签 |
| `status` | 是 | `draft`（只有原文）→ `translated`（有白话，待审）→ `reviewed`（主线审过） |

支线提交时 status 最多到 `translated`；`reviewed` 由主线审核后改。

## 适用条件 `applies`

每个条件是一个对象，必须带 `module`；不同模块允许的键和取值：

| 模块 | 键 | 取值 |
| --- | --- | --- |
| 通用 | `note` | 自由文字，用于无法编码的条件 |
| 通用 | `gender` | 男 / 女 |
| `ziwei` | `star` / `stars` | 星名（紫微、天机……擎羊、陀罗……见 schema.js 的 ZIWEI_STARS）；写数组时任一颗在宫就算，只用于原文本意就是任一颗的（「四煞守身命」「魁钺命身」） |
| `ziwei` | `allStars` | 两颗以上星名，几颗都要在同一宫才算（原文「同宫」「同守」「同垣」「某某同度」，以及「武曲贪狼」「廉贞七杀」「武曲会擎羊」「火铃相遇」这类要几颗同在才成立的断语） |
| `ziwei` | `jia` | 左右两邻各坐一颗、夹住本宫的两个名字：星名，或四化写成「化禄」「化权」「化科」「化忌」（「昌曲夹命」写 `["文昌", "文曲"]`，「羊陀夹忌」写 `["擎羊", "陀罗"]` 再加 `mutagen: "忌"`，「权禄夹」写 `["化权", "化禄"]`）；哪边是哪颗不论 |
| `ziwei` | `palace` | 命宫、身宫、兄弟、夫妻、子女、财帛、疾厄、迁移、仆役（交友）、官禄（事业）、田宅、福德、父母 |
| `ziwei` | `branches` | 地支数组 |
| `ziwei` | `brightness` | 庙 / 旺 / 得 / 利 / 平 / 不 / 陷 |
| `ziwei` | `mutagen` / `mutagenAll` | 禄 / 权 / 科 / 忌：本宫星曜带的生年四化（看运限层时再加该层四化到本宫星的）。`mutagen` 任一化（可写数组），`mutagenAll` 几化都要在同一宫（「禄权同守」「双禄交流」写 `star: "禄存", mutagen: "禄"`、「科权同宫」写 `mutagenAll: ["科", "权"]`） |
| `ziwei` | `meetMutagen` / `meetMutagenAll` | 禄 / 权 / 科 / 忌：本宫连三方四正里的四化（「拱」「会」「照」）。`meetMutagen` 任一化，`meetMutagenAll` 几化都要有（「科权对拱」写 `palace: "命宫", meetMutagenAll: ["科", "权"]`，「权禄巡逢」写 `meetMutagenAll: ["权", "禄"]`；科权禄三化齐会命宫三方四正的直接写 `pattern: "三奇加会"`） |
| `ziwei` | `pattern` | 程序认得出的格局名（见下「格局名与神煞名」），带不带「格」字都行 |
| `ziwei` | `limit` | 本命 / 大限 / 小限 / 流年 / 流月 / 流日（大限、小限、流年的条件只在看那一层时命中：此刻大限、小限、流年命宫所落的本命宫；原文「二限」「岁限」写大限、小限两条）。看大限、流年时，排盘库那一层的流曜也算进本宫与三方四正的星——流羊、运羊算擎羊，流陀算陀罗，流昌流曲算文昌文曲，流魁流钺、流禄、流马、流鸾流喜同理——该层四化到本宫星的也算 `mutagen`（小限只有四化，排盘库不给小限流曜）；命中说明注「（流年）」「（大限）」「（小限）」。所以「流年又遇流羊流陀」写 `limit: "流年", meetAll: ["七杀", "擎羊"]` 即可，不用另写流曜名 |
| `ziwei` | `empty` | 固定写 `"无正曜"`：这一宫没有主星才命中（「命无正曜」「本宫无正曜」「左右单守」）；程序给空宫借对宫主星一起找原文，借了星也还算空宫 |
| `ziwei` | `yearGan` / `yearZhi` | 生年干、生年支（数组任一；排盘库按农历年给年柱）：「壬甲生人」写 `yearGan: ["壬", "甲"]`，「六癸生人」写 `yearGan: "癸"`，「寅午戌生人」「子年生人」写 `yearZhi`。原文把生年当附加条件的（「甲丁己癸生人福」），保留原条件再加一条带年干的，命中时排前；当必要条件的（「昌曲己辛壬生人限逢辰戌」）直接写进条件。纳音「水生人」「火生人」程序还没有，写 `note` |
| `ziwei` | `bureau` | 五行局：水二局 / 木三局 / 金四局 / 土五局 / 火六局（数组任一；排盘库按命宫干支纳音定局）。《全书》论限歌「金人遇坎命须伤，木命落离有祸殃」的「金人」「木命」是金四局、木三局的人，写 `bureau: "金四局", limit: "大限", branches: ["子"]`（坎＝子，离＝午，艮＝丑寅，兑＝酉，震＝卯，巽＝辰巳）；「水木二局」写 `bureau: ["水二局", "木三局"]` |
| `ziwei` | `hourZhi` | 生时地支（排盘用的时辰，数组任一）：「生在寅午戌申子辰六阳时，安命在此六宫者吉」写 `palace: "命宫", branches: [六阳支], hourZhi: [六阳支]`；「寅午巳酉生人见辰戌丑未时」写 `yearZhi: [...], hourZhi: [...]` |
| `ziwei` | `meet` / `meetAll` | 星名数组：本宫连三方四正（对宫与两个三合宫）里有这颗星（「会」「拱」「照」「朝」「冲」）；`meet` 任一颗在就算，`meetAll` 几颗都要有（「府相朝垣」写 `meetAll: ["天府", "天相"]`，「巨日拱照」写 `meetAll: ["太阳", "巨门"]`，「武曲会擎羊」写 `star: "武曲", meet: ["擎羊"]`）。只数主星、辅星，杂曜不算。写之前按安星法想一想两颗星到底会不会落在三方四正：太阳与七杀、廉贞与巨门之类永远不会，这种原文只写 `note` |
| `ziwei` | `flow` / `flowAll` | 流曜名数组（排盘库的叫法：流年的流昌、流曲、流魁、流钺、流禄、流羊、流陀、流马、流鸾、流喜，大限的运昌、运曲……）：该层飞到本宫或三方四正的流曜，`flow` 任一颗、`flowAll` 几颗都要有，必须同时写 `limit: "大限"` 或 `"流年"`。只有原文点明流曜、要与本命星分开的才用（「擎羊重逢流羊」写 `limit: "流年", star: "擎羊", flow: "流羊"`；「流年又遇流羊流陀」写 `flow: ["流羊", "流陀"]`）：条件里一写 `flow`，同条件的 `star` / `meet` 就只算本命的星，不再把流羊兼算作擎羊。原文只说「限逢擎羊」的照常写 `star`，流曜会自动算进去 |
| `ziwei` | `doujun` | 流年斗君（正月）所落的本命宫名（十二宫名，奴仆、交友算仆役），必须同时写 `limit: "流年"`。斗君按《全书》卷一安流年斗君诀算：太岁宫（流年命宫）起正月逆数至生月，再从生月起子时顺数至生时；闰月生过十五按下月，与排盘安命宫一致。十二宫论每宫末尾的「斗君过度在此宫逢吉……逢凶……」写 `{ "limit": "流年", "doujun": "夫妻" }`，看流年层时命中（界面与提示词都标出斗君所在宫）；斗君每月顺行一宫，其余月份过度到该宫时的吉凶程序不逐月判，在 `note` 里说明 |
| `bazi` | `dayGan` / `dayGans` | 日干 |
| `bazi` | `monthZhi` / `monthZhis` | 月支 |
| `bazi` | `tenGod` / `tenGods` | 十神名 |
| `bazi` | `pattern` / `shensha` | 程序判得出的格局名、神煞名（见下「格局名与神煞名」） |
| `bazi` | `relation` | 合冲刑害：`冲`、`合`、`半合`、`三合`、`三会`、`刑`、`自刑`、`害`、`破`，或具体如 `子午冲`、`乙庚合` |
| `bazi` | `strength` | 极弱 / 偏弱 / 中和 / 偏强 / 极强 |
| `bazi` | `season` | 春 / 夏 / 秋 / 冬 / 四季 |
| `bazi` | `liuqin` | 夫妻 / 子女 / 父母 / 兄弟：讲某一种六亲的（《滴天髓》六亲论诸篇、《子平真诠》论妻子等）。带 `liuqin` 的条件只在八字结果页「六亲宫星」那一亲下面命中，不进「古籍原文」总列表（同一条目另写了不带 `liuqin` 的条件，按那一条照常进总列表）；可与 `gender`、`tenGod`、`strength` 等同写，如以财为妻的男命说法写 `{ "module": "bazi", "liuqin": "夫妻", "gender": "男" }` |
| `liuyao` | `hexagram` / `hexagrams` | 六十四卦全名（乾为天、水雷屯……） |
| `liuyao` | `line` | 1–6 |
| `liuyao` | `relation` | 六冲 / 六合 |
| `liuyao` | `sixRelative` | 父母 / 兄弟 / 子孙 / 妻财 / 官鬼 |
| `liuyao` | `sixGod` | 青龙 / 朱雀 / 勾陈 / 螣蛇 / 白虎 / 玄武 |

| `liuyao` | `movingLines` | 无 / 一 / 多 |

## 格局名与神煞名

## 程序怎么用这些条件

`src/data/classics/library.js` 把所有文件合成索引，页面按当前命盘 / 卦的上下文找条目：八字结果页「古籍原文」一节、紫微专业盘「常用功能 → 古籍原文」（按宫看，命宫另带程序认出的格局）、六爻结果页「古籍原文」卡（有命中才显示）；命中的原文也会附进各模块导出给 AI 的提示词。

- 一个条件里的每个键都要满足（`module` 必须相同）；键值是数组时「任一」满足即可；`stars`/`tenGods`/`dayGans`/`monthZhis`/`hexagrams` 与单数键同义。例外是紫微的 `allStars`、`meetAll`：列的几颗星都要在（同宫 / 三方四正）；`jia`：两个名字分坐左右两邻。
- 八字上下文里有：日干、月令、十神（透干与藏干都算）、神煞、格局（含同义名：正财格也算财格，羊刃格也算阳刃格、刃格，建禄格 / 月劫格也算建禄月劫，杂气正财格也算正财格）、季节（辰戌丑未月同时算「四季」）、旺衰、合冲刑害（写 `冲`、`子午冲`、`三合` 这类都能对上）、性别。
- 紫微上下文：所选宫的全部星曜（主星、辅星、杂曜）、左右两邻的星曜与四化（判「夹」）、宫名（身宫同宫时两个都算）、地支、庙旺、四化、性别、生年干支、五行局、生时地支、运限层（本命；古籍弹层切到「当前大限」「今年流年」时，是此刻所行大限、流年的命宫，写 `limit: 大限` / `limit: 流年` 的条目在这两层出现）；看命宫时另带程序认出的格局。
- 紫微条件还表达不了的（待程序补键，先只写 `note`）：跨宫的四化组合（「权禄守财官之位」里权在财帛、禄在官禄的分宫情形，`mutagenAll` 只核同一宫）；大限、小限、流年三层同时并临（「岁限俱到」「二限太岁交临」）；纳音「水生人」「火生人」；岁前诸星（官符、白虎、吊客、丧门）。

## 内容规范

- 原文来自公版古籍，择善本，注明来源；繁体文本要统一转简体后逐字校对（转换容易出错的字：云/雲、后/後、干/幹、里/裏、发/發、余/餘、系/係、几/幾、制/製、征/徵、斗/鬥、谷/穀、适/適）。
- 白话必须自己写，不得抄录任何现代校注本、今译本或网络译文。
- 一条控制在原文 300 字以内，长篇按自然段拆条，`id` 序号递增。
- 不加原文没有的内容；拿不准的句子写进 `doubts`，不要猜着翻。
- 涉及人名、朝代、官职的，白话保留原词并在 `notes` 简释。
