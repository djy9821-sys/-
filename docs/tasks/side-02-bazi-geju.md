## 第 5 批：《滴天髓》六亲论

主线结果页新增了「六亲宫星」一节（配偶、子女、父母、兄弟各看星与宫），每一亲下面会列古籍库里讲这一亲的原文；`applies` 为此新增了 `liuqin` 键（取值 夫妻 / 子女 / 父母 / 兄弟，见 README）。这一批就是给它供原文。

- **底本**：公版《滴天髓》原文与原注（旧题刘基注），维基文库、ctext 等公版录文均可，`edition` 写明所据。**只录原文与原注**：任铁樵「任氏曰」增注及其中命造不录（命造由 side-05 收作命例），徐乐吾补注、现代白话本一律不用。
- **分支**：`side/02-ditian-liuqin`，从 `origin/claude/round8-collab` 新开（要有主线刚加的 `liuqin` 键，不然校验报「不允许的键」）；PR 的 base 选 `claude/round8-collab`。
- **怎么拆**：原书一段原文（通常两句一联）连同其下原注为一条。`original` 先写原文，换行后写「原注：……」；`title` 用「夫妻·其一」。原文与原注都要白话，逐句直译（要求同上「白话要求」），`status` 写 `translated`。
- **applies**（每个条件都带 `"module": "bazi"`）：
  - 夫妻篇以财为妻，是男命的看法：`{ "liuqin": "夫妻", "gender": "男" }`；子女篇以官杀为子女：`{ "liuqin": "子女", "gender": "男" }`。原注明说男女通论的句子不写 `gender`。
  - 父母篇 `{ "liuqin": "父母" }`；兄弟篇 `{ "liuqin": "兄弟" }`。
  - 女命篇：论夫的 `{ "liuqin": "夫妻", "gender": "女" }`，论子的 `{ "liuqin": "子女", "gender": "女" }`，夫子并论的 `liuqin` 写数组 `["夫妻", "子女"]`；泛论女命的只写 `{ "gender": "女" }`。
  - 从象、假从：`{ "pattern": "从格" }`，专讲某一种的写具体格名（从财格、从杀格、从儿格、从势格）；化象、假化：`{ "pattern": "化气格" }`，专讲某一化的写如「甲己化土格」。
  - 战局：地战（地支相冲）写 `{ "relation": "冲" }`，天战写 note；合局写 `{ "relation": "合" }`。
  - 何知章、小儿、才德、奋郁、恩怨、闲神、顺局、反局、君象、臣象、母象、子象、性情、疾病、出身、地位、岁运、贞元：程序不判这些，写 `note` 说明讲的是什么，不要硬编十神、旺衰条件。
- **先后**：先交夫妻、子女、父母、兄弟、女命五篇（主线等着用），这五篇做完先跑校验、提交、推送一次；其余各篇随后，每篇提交一次。
- **验收**：`node scripts/validate-data.mjs` 与 `node scripts/applies-coverage.mjs` 都过；PR 里列出所据版本、各篇条数、与通行本文字有出入之处（写在条目 `doubts`）。

## 来源

公版古籍文本（ctext.org、维基文库、国学导航等），繁转简逐字校对，`edition` 写明。**不得使用现代校注本、白话本、网文译文。**

## 条目怎么拆

- 每章按自然段拆，一段一条，`title` 用「论用神·其一」「论正官·其三」。
- 段中给出命例（如「甲生酉月…」）的，命例作为该条的一部分保留在原文里，不要单独抽出。
- `applies`：论某格的写 `pattern`（正官格、七杀格、食神格、伤官格、正财格、偏财格、正印格、偏印格、阳刃格、建禄格、月劫格）；论某十神的写 `tenGod`；论季节调候的写 `season`；论某日干的写 `dayGan`。编不出来写 `note`。
- 第 4 批神煞：每条写 `{ "module": "bazi", "shensha": "驿马" }`，神煞名必须与 `SHENSHA_ORDER` 一字不差（书中叫咸池的写「桃花」，叫阳刃的写「羊刃」）；查法口诀与程序查法不同的照录原文，在 `doubts` 写明「与程序查法不同：……」，不要改原文去凑程序。一条只讲一个神煞；同段兼论几个的，`applies` 列几条。

## 白话要求

- 子平法术语（用神、相神、忌神、透、通根、制、化、合去、冲、刑）保留原词，第一次出现时在 `notes` 简释。
- 原文里的推理链（「官格用财，财生官；见伤则破格，有印则救」）白话必须完整翻出，不要缩成结论。
- 翻不准写 `doubts`。
- 逐句直译：原文一句对白话一句，不加原文没有的解释、例子和感叹（第 3 批返工就是因为铺陈过度）；要补充的背景写进 `notes`。
