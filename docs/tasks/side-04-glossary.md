# side-04 术语白话词典

先读 `docs/AI协作手册.md`。

## 目标

客户看不懂「化忌」「旬空」「伤官见官」是什么意思。做一本三模块共用的术语词典：每个术语一句话解释 + 几句白话展开 + 一个例子 + 出处，给界面「术语说明」、结果页悬浮提示和 AI 提示词用。

## 产出文件

- `src/data/glossary/bazi.json`（已有 2 条示例，在其后续加）
- `src/data/glossary/ziwei.json`
- `src/data/glossary/liuyao.json`
- `src/data/glossary/common.json`（三模块共用：天干、地支、五行生克、阴阳、纳音、节气、真太阳时、晚子时、农历闰月）

## 格式

```json
{
  "module": "bazi",
  "entries": [
    {
      "id": "shang-guan-jian-guan",
      "term": "伤官见官",
      "aliases": ["伤官见官，为祸百端"],
      "brief": "命局里伤官和正官同时出现，传统视为需要留意的组合。",
      "explain": "伤官是「我生」的阴阳异性之神，正官是「克我」的阴阳异性之神，伤官专克正官……（2–5 句，说清是什么、为什么、怎么看）",
      "example": "日主甲木，见丁火是伤官，见辛金是正官；两者同在天干，就是伤官见官。",
      "source": { "classic": "yuanhai", "section": "伤官论" },
      "related": ["伤官", "正官", "伤官配印"]
    }
  ]
}
```

字段：`term` 必填且同模块内唯一；`brief` 必填、60 字以内、一句话；`explain` 必填、20 字以上、白话；`example` 选填；`source` 选填但鼓励写（`classic` 必须是 `src/data/classics.js` 登记表里的 key）；`aliases`、`related` 选填；`id` 选填（小写拼音加短横）。`node scripts/validate-data.mjs` 会校验。

## 白话要求

- 面向完全不懂的客户：先说「是什么」，再说「怎么看」，最后说「意味着什么」；不下吉凶断语，不吓人。
- 术语之间互相引用用 `related`，不要在 `explain` 里展开另一个术语。
- 有流派差异的（如晚子时、阴刃、天乙贵人口诀异说）要点明「两说并存，本程序取哪一种」——程序口径看 `src/utils/` 里的注释和 `PROJECT_HANDOFF_2026-10-25.md` 的「流派口径备忘」。
- 出处尽量给到篇章；给不出就不填 `source`，不要编。

分支 `side/04-glossary`；一个模块一个 PR 也可以，或三模块一个 PR。校验脚本与 CI 通过；抽查 10 条看是否准确、通俗、无吉凶渲染。只产出 JSON，不碰代码；不接界面（接界面是主线的事）。
